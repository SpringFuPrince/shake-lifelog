# 拾刻生活记录分析

拾刻采集、保存并同步记录，通过 Mac 上的只读 MCP 提供图文。当前 Agent 负责从记录中找证据、做计算并回答用户。拍摄和手动记录使用同一数据模型，照片、备注和字段都可能单独存在。

## 读取记录

1. 把问题转成日期范围、类别和所需证据。用用户的日历理解相对日期。「上周」默认为上一个完整周，「近 7 天」为含今天的滚动窗口。记录以各自保存的当地日期归组。时间未指定时，查单条取最近相关记录，做对比则选符合目标的窗口并在答案中注明日期。
2. 有记录 ID 用 `get_records`，其余用 `search_records`。查某个主题时可用关键词，可能只有照片时按日期和类别找。完整回顾翻到末页，长期回顾按所需类别及时间段分批查询。只看部分记录时，用实际覆盖范围描述发现。调用参数见 [MCP 查询](references/tools.md)。
3. 检查与问题相关的照片，通过 `photo.content_index` 配对同一响应中的图与文。看不清关键小字或秤屏时，按原 ID 读取高清图。用用户本次提供的信息和记录中的自述补充图片，保留默认字段、可见内容与估算各自的证据分量。
4. 照片暂不可读时继续用可靠文字和字段回答。查无结果时先核对日期、类别、关键词与同步范围，区分 Mac 上没有匹配项、媒体缺失和服务不可用。接入或排查时读 [接入说明](setup.md)。

## 分析和呈现

- 分析某类记录时，按需读 [五类分析](references/analysis.md) 中对应章节。做周月对比、跨类回顾或延续一个目标时，读 [长期跟踪](references/tracking.md)。历史「日常」可为事件回顾提供背景。
- 先回答用户最想知道的变化或事实，再用日期范围、数字和几条代表记录说明依据。给出的数字用对应单位，明确是记录条数、独立事件数、有效样本数还是估算。对影响理解的缺口，用一句自然的话交代。
- 单条和简短问题直接答。周期和多类对比用短表，连续变化可用带日期、单位和缺测留白的折线，类别或分布适合条形图。知识回顾可按主题列出要点和出处，重温经历可用简短时间线。根据问题取舍，看完结论即可找到关键变化。
- 主要结论附能回到原记录的日期、餐次、时间或标题。客户端支持记录链接时使用可用的真实链接。需逐条核对、同日同名难以区分或用户要导出时附原始 ID。建议随用户目标给出，优先给可以执行或在下次复盘验证的一步。
